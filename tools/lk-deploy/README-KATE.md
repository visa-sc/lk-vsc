# Выкладка визового личного кабинета — инструкция

С 16.10.2026 вы сами выкладываете на боевой два файла визового ЛК:

- `cabinet.html` — сам кабинет (voyotravel.ru/cabinet);
- `index.html` — страница входа (voyotravel.ru).

Остальное (опросники и вся серверная часть, eSIM, «Карты», «Баллы», экскурсии) пока остаётся за Андреем. Если для задачи нужно поменять что-то из этого, напишите ему.

## Как это устроено

Прямого доступа к основному приложению у вашего пользователя нет и не будет: там общий файл со всеми ключами. Вы работаете в папке `~/lk-deploy` на сервере (пользователь `kateadmin`, как обычно). Команда `lkdeploy` оставляет в этой папке заявку. Служба сервера сама берёт оттуда ваши файлы, проверяет их и выкладывает. Перед каждой выкладкой она сохраняет копию прежней версии, так что откат делается одной командой.

## Команды

```
lkdeploy pull              взять свежие боевые cabinet.html и index.html в ~/lk-deploy
lkdeploy status            что у вас отличается от боевого
lkdeploy check             проверить свои файлы, ничего не выкладывая
lkdeploy preview           показать свою версию по секретной ссылке — клиенты её не видят
lkdeploy deploy            выложить на боевой (нужен ~/lk-deploy/CHANGELOG.md)
lkdeploy rollback ФАЙЛ     вернуть предыдущую версию: lkdeploy rollback cabinet.html
lkdeploy log               последние выкладки
```

## Порядок работы

1. **`lkdeploy pull`** — всегда перед началом правок. Файлы в `~/lk-deploy` станут такими же, как на боевом. Если у вас там уже были свои правки, их команда не тронет: свежую боевую версию положит рядом как `cabinet.html.prod`. Тогда перенесите свои правки в неё, сохраните как `cabinet.html` и удалите `.prod`. Пока `.prod` лежит, выкладка не пойдёт.
2. Правьте `~/lk-deploy/cabinet.html` / `index.html`.
3. **`lkdeploy preview`** — команда даст ссылку вида `https://voyotravel.ru/lk-preview/cabinet?k=…`. Войдите в кабинет как обычно (или откройте клиента через «Вход в ЛК клиента» в админке) и откройте ссылку. Вы увидите свою версию на настоящих данных, клиенты её не видят. Проверьте на телефоне и на компьютере.
4. Опишите изменение в **`~/lk-deploy/CHANGELOG.md`**: первая строка — заголовок, дальше пункты через «- ». Пример:
   ```
   Кнопка «Заполнить опросник» стала заметнее
   - Кнопка зелёная и на всю ширину на телефоне
   - Текст под кнопкой сокращён
   ```
   Эта запись автоматически появится в админке: «База знаний ЛК» → «История изменений». Без неё выкладка не пойдёт.
5. **`lkdeploy deploy`**. Служба по очереди:
   - проверит, что боевой файл никто не менял после вашего pull — чтобы вы случайно не затёрли чужую правку;
   - проверит файлы: кодировку и то, что во встроенных скриптах нет синтаксических ошибок, способных положить кабинет;
   - сохранит копию прежней версии и выложит новую;
   - убедится, что сайт отдаёт новую версию. Если нет — сама всё вернёт и напишет об этом.
6. Откройте voyotravel.ru/cabinet и проверьте глазами. Если что-то не так — **`lkdeploy rollback cabinet.html`**.

## Важно

- **Описание кабинета в админке.** Если правка меняет логику — этапы, документы, что видит клиент на каком этапе, — описание кабинета в админке («Тестировщик ЛК», «Экраны клиента», «Карта документов») само не обновится: оно живёт в server.js. Напишите Андрею, что поменялось, он обновит. Журнал изменений обновляется сам, из вашего CHANGELOG.md.
- **Не ослаблять вход.** Кабинет получает данные только по сессии входа, не по номеру телефона в адресе. Это защита паспортных данных.
- **Телефон и компьютер.** Кабинетом в основном пользуются с телефона, проверяйте на узком экране (320–390 px).
- **Параллельные правки.** Андрей тоже иногда выкладывает правки кабинета. Если `deploy` говорит, что боевой изменился после вашего pull, сделайте `pull` и перенесите правки в свежую версию.
