# Сервер распознавания звонков — инструкция

Машина **«VSC обработка звонков»**, `194.58.95.110`, Ubuntu 24.04 LTS.
Она полностью ваша: у пользователя `kate` есть sudo без пароля, ставьте и
пересобирайте что нужно. Обращаться к Андрею требуется только в одном
случае — если не хватит процессора, памяти или диска (см. «Ресурсы»).

## Вход

```bash
ssh kate@194.58.95.110
```

Вход только по ключу — тот, что вы присылали (`kateadmin@voyotravel`).
Вход по паролю на сервере отключён.

## Что уже стоит

`ffmpeg`, `cmake`, `make`, `gcc`, `g++`, `python3` + `pip` + `venv`, `git`,
`htop`, `tmux`. Файрвол пропускает только SSH, автообновления включены,
подключён swap 2 ГБ (страховка от нехватки памяти при загрузке модели).

Сам Whisper не ставили — вы просили собрать самостоятельно:

```bash
git clone https://github.com/ggml-org/whisper.cpp && cd whisper.cpp
cmake -B build && cmake --build build -j$(nproc)
bash ./models/download-ggml-model.sh medium
```

Модели кладите в `/opt/asr/models`.

## Каталоги

| Путь | Назначение |
|---|---|
| `/opt/asr/audio` | записи звонков — **чистятся автоматически**, старше 30 дней удаляются |
| `/opt/asr/text` | транскрипции — хранятся бессрочно |
| `/opt/asr/models` | модели whisper |

Автоочистка — `/etc/cron.daily/asr-cleanup`, раз в сутки. Сделана и ради
экономии диска (его всего 20 ГБ), и потому что записи разговоров — это
биометрические персональные данные, держать их дольше нужного не стоит.
**Транскрипции она не трогает.**

## Обработка стереозаписи

Записи 8 кГц стерео: менеджер и клиент в разных каналах. Перед распознаванием
разделите каналы и поднимите частоту до 16 кГц — так модель ошибается заметно
меньше и точно понятно, кто что сказал:

```bash
ffmpeg -i call.mp3 -filter_complex 'channelsplit=channel_layout=stereo[l][r]' \
  -map '[l]' -ar 16000 -ac 1 manager.wav \
  -map '[r]' -ar 16000 -ac 1 client.wav
```

Какой канал чей — проверьте на паре записей, в onlinePBX порядок каналов
зависит от направления звонка.

## Передача результатов на основной сервер

На этой машине только обработка. Готовые транскрипции отправляйте на основной
сервер, где живёт ваш модуль качества:

```bash
rsync -a /opt/asr/text/ kateadmin@89.108.88.59:
```

Файлы окажутся в `/var/www/kateadmin/data/asr/` — рядом с вашими `cq*.json`.

Канал намеренно односторонний и узкий: ключ этой машины умеет **только**
заливать файлы в этот каталог. Шелл, чтение чужих файлов и любые другие
команды с него невозможны — так распознавание не получает доступа к боевым
данным и платёжным ключам основного сервера.

## Ресурсы

2 ядра, 4 ГБ памяти, 20 ГБ диска. Под выборку (порядка 400 звонков в месяц)
этого достаточно: около 20 часов аудио, считается ночами.

Если упрётесь — напишите Андрею, конфигурацию поднимут за пару минут прямо
в панели. Признаки, что пора: распознавание не укладывается в ночь (нужны
ядра), процесс убивает по нехватке памяти (нужна память), или `df -h`
показывает меньше 3 ГБ свободного (нужен диск).

## Что стоит знать

- Резервных копий у машины нет: всё на ней воспроизводимо, а записи всегда
  можно перекачать из amoCRM заново. Поэтому **транскрипции не должны жить
  только здесь** — отправляйте их на основной сервер, как описано выше.
- Наружу машина ничего не публикует, порт для веб-сервисов не открыт.
  Если понадобится — правьте `ufw` сами.
