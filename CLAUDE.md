# Правила работы в этом репозитории

## Карта структуры — ak-co.ru/map

Вся структура бизнеса (домены, поддомены, сервисы, страницы, разделы внутри
страниц, фоновые задачи) собрана на одной странице: **https://ak-co.ru/map**
(вход тот же, что у личных финансов — код и Face ID).

Карта **не поддерживается руками**. Её собирает `tools/sitemap-scan.js` прямо из
живой инфраструктуры боевого сервера: конфиги nginx, процессы pm2, объявления
`app.get/post/use` в коде, вкладки `data-tab` / `data-go` / `TABS[...]` в html,
`sitemap.xml` сайта, `crontab`. Запускается по cron каждый час (`17 * * * *`),
снимок кладётся в `/var/www/akfin/.sitemap.json`.

Сканер сравнивает новый снимок с предыдущим. Всё появившееся и пропавшее
попадает в раздел «Изменения структуры» на карте, и на director@visa-sc.ru
уходит письмо. Поэтому новую страницу, поддомен или раздел невозможно завести
мимо карты — она сама их увидит в течение часа.

### Что обязан сделать любой, кто добавляет страницу или раздел

Сканер найдёт новый путь сам, но **зачем он нужен и кто имеет к нему доступ** из
кода не вычитывается. Поэтому:

> **Добавил страницу, раздел, поддомен или сервис — в том же коммите допиши
> строку в `tools/sitemap-notes.json`.**

Проверка перед деплоем (работает локально, боевой сервер не нужен):

```bash
node tools/sitemap-scan.js --check
```

Команда печатает страницы без пояснения и возвращает код 1, если такие есть.
Непрописанная страница всё равно появится на карте, но с красной пометкой
«без описания» — так что незамеченной не останется, просто будет выглядеть
недоделкой.

Формат строки:

```json
"/путь": { "group": "Клиент", "access": "кто входит", "desc": "что это такое" }
```

Группы: `Клиент`, `Поиск`, `Управление`, `Рабочее место`, `Личное`, `Лендинги`,
`Служебное`. Поле `access` — человеческими словами («код 3451», «только админ»,
«клиент по сессии»), не имена функций. Для семейства однотипных страниц можно
писать шаблон со звёздочкой: `"/esim/*"`.

Там же, в `sitemap-notes.json`, живут списки, которые из кода не достать:
внешние системы (`external`), сторожа (`watchdogs`) и где лежат данные
(`storage`). Завели интеграцию или сторожа — строка туда же.

### Полезные команды

```bash
node tools/sitemap-scan.js --check   # что не описано (локально)
node tools/sitemap-scan.js --dry     # весь разбор в консоль, ничего не писать
node tools/sitemap-scan.js --quiet   # пересобрать снимок без письма (на сервере)
```

Кнопка «Обновить» на самой карте делает то же, что `--quiet`, — на случай
«только что выкатили, хочу видеть сейчас».

## Расход Claude API — каждый сервис обязан отчитаться

Сторож баланса (`ai-balance.js`) шлёт письмо о балансе Claude API с разбивкой
по сервисам. Строки в письме собираются сами из журналов, поэтому любой новый
код, который обращается к Claude, подключается к учёту одним из двух способов:

1. **Через шлюз** основного приложения (`/internal/anthropic`, ключ шлюза
   вместо настоящего) и заголовок `x-voyo-service: <имя-сервиса>`. Так ходят
   переводы, прослушка и Катин сканер.
2. **Своим ключом** — тогда после каждого ответа модели:
   `require("./ai-usage").record("<имя-сервиса>", msg.model, msg.usage)`.

Название строки для нового сервиса — в `SVC_SHORT` в `ai-balance.js`. Без него
строка всё равно появится, только под техническим именем.

Раз в сутки сторож обходит код в `/var/www` и ищет обращения к Anthropic, не
подключённые к учёту. Найденные выводятся в письме красным: значит, деньги
уходят, а в разбивке их нет.
