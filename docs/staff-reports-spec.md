# Недельные стафы руководителей — что в них считается

Разбор пяти файлов, которые руководители вели вручную (Андрей прислал 11.09.2026).
Сами файлы лежат рядом в `docs/staff-reports/` (папка в .gitignore, как `legal/` и
`fdoc-reference/`), копия — на проде в `/var/www/voyo/docs/staff-reports/`.
Этот документ нужен, чтобы логику можно было восстановить без файлов.

## 1. Отдел продаж — «Staff Performance OП.xlsx»

Вкладка на каждую неделю с октября 2021 года. Строка на менеджера.

| Колонка | Смысл |
|---|---|
| B | План лидов (новых контактов) за период |
| C | План по ATV для новых заявок |
| D | План по конверсии для новых заявок |
| E | План выручки = B × C × D |
| F | Фактически набранные лиды за период (из CRM, МСК + СПб) |
| G | План от фактически набранных = F × C × D (база бонуса) |
| H | Сделки по новым заявкам (из CRM) |
| I, J | Сделки со скидкой и их доля |
| K | Сумма личных продаж по новым заявкам |
| L, M | Возвраты и чистые продажи (M = K − L) |
| N | Выполнение плана выручки = K / G |
| O, P | Конверсия факт = H / F и её выполнение = O / D |
| Q, R | ATV факт = K / H и его выполнение = Q / C |
| S, T | Ставка бонуса и бонус = M × S |
| U, V | Повторные продажи и бонус 7% |
| W, X | Третья база и бонус 11% |
| Y | Итого бонус = T + V + X |

Вторая таблица листа: сделки и обработанные контакты в разрезе МСК/СПб и конверсия
по каждому городу, плюс «недобор по таргету» = F − B.

✅ Перенесено: контакты, продажи, выручка, средний чек, конверсия по каждому менеджеру.
Продажи считаются **по автору сделки**: после продажи ответственный меняется на
специалиста ОРК, и по «ответственному» продажа уезжает из отчёта менеджера.

⚠️ Не сошлось: их H (сделки по новым заявкам) больше, чем все оплаченные сделки
менеджера за месяц. У Егошина в неделе 24–31 августа стоит 11, а по оплатам в CRM за
весь август 5. По какому фильтру берётся H — вопрос к РОПу.

Не перенесено: планы, ставки и расчёт бонусов — это не отчётность, а мотивация.

## 2. ОРК Москва и ОРК Петербург — «Staff Performance OРК МСК 2025.xlsx», «Staff Performance ОРК СПБ.xlsx»

Это **не** отчёт по людям, а модель загруженности отдела. Отдельные блоки для
СПЕЦИАЛИСТОВ и АДМИНИСТРАТОРОВ. На каждый тип активности задан норматив минут, он
умножается на количество за период, сумма переводится в часы и делится на доступные
часы штата — получается процент загруженности и изменение к прошлой неделе.

Нормативы, минут за единицу (Москва / Петербург совпадают):

| Категория | Активность | Единица | Норматив |
|---|---|---|---|
| Приём и встречи | Визит без оплаты | сделка | 20 |
| | Первичная консультация | сделка | 30 |
| | Встреча в офисе | сделка | 40 |
| | Дистанционный приём | сделка | 10 |
| Подготовка для ОО | Полный сбор документов | заявитель | 17 |
| | Неполный сбор документов | заявитель | 10 |
| Подготовка к подаче | Электронный пакет | заявитель | 5 |
| | Печать | заявитель | 10 |
| | Сложная печать | заявитель | 20 |
| Передача и завершение | Выдача курьеру | заявитель | 7 |
| | Выдача в офисе с консультацией | заявитель | 35 |
| | Выдача в офисе без консультации | заявитель | 15 |
| | Дистанционная выдача с консультацией | заявитель | 25 |
| | Дистанционная выдача без консультации | заявитель | 2 |
| | Выдача паспорта после безличной подачи | заявитель | 5 |
| Операционная | Чаты | диалог | 5 |
| | Звонки | минута | 1 |
| | Задачи amoCRM | задача | 3 |
| | Отчёты и закрытия, будний день | день | 60 |
| | Отчёты и закрытия, выходной | день | 30 |

Откуда берутся количества (колонка «Путь фильтрации» в файле):

- **Визит без оплаты** — задачи amoCRM, дата создания в периоде, тип задачи «Визит без
  оплаты», ответственные — руководители ОРК.
- **Первичная консультация** — сделки, созданные в периоде, воронка отдела продаж, тип
  сделки «С улицы», создана специалистом отдела.
- **Встреча в офисе / Дистанционный приём** — сделки с датой оплаты в периоде, поле
  «Кто принял» — специалисты отдела, разделение по полю «приём документов»: встреча и
  выездное оформление против почты и мессенджера. Берётся количество заявителей.
- **Полный и неполный сбор документов** — сделки в статусах от «Передано в ОО» и ниже
  плюс вся воронка оформления, «Дата начала работы ОО» в периоде, «Кто принял» —
  специалисты отдела, разделение по стране оформления.
- **Выдачи** — сделки от статуса «На рассмотрении в Консульстве» и ниже, дата записи на
  подачу в периоде; с консультацией — Шенген, США и Великобритания, без консультации —
  все остальные страны.
- **Выдача паспорта после безличной подачи** — статус «Успешно реализовано», дата
  реализации в периоде, способ подачи безличный, акт подписал специалист отдела.
- **Чаты** — Wazzup, аналитика по сотрудникам, число диалогов за период.
- **Звонки** — PBX, минуты разговора по добавочным специалистов, кроме групповых.
- **Задачи amoCRM** — задачи с датой закрытия в периоде, ответственные — специалисты
  отдела, статус задачи неважен.

✅ Перенесено частично: сделки, выручка, средний чек, возвраты и нагрузка на человека.
По людям сделка считается по полю «Кто принял клиента» (443488) — оно заполнено почти
у всех сделок и раскладывает объём месяца по специалистам.

❌ Не перенесено: сама модель загруженности в минутах. Нужны счётчики по типам активности
(задачи amo по типам, заявители по видам выдачи, диалоги Wazzup, минуты PBX) и доступ к
API АТС, которого в проде нет.

## 3. Отдел оформления — «КАЛЬКУЛЯТОР ОО.xlsx»

Актуальный файл (старый «Staff Performance OO 2025.xlsx» Андрей отменил).
Стаф живёт на вкладке «РЕЙТИНГ», расшифровка показателей — на вкладке «Расшифровка».

Таблица продуктивности, на сотрудника за неделю:

| Код | Смысл |
|---|---|
| S1 | Количество закрытых первых этапов |
| S1-T, S1-M | Нормативное время и бонус за первые этапы |
| S2 | Количество закрытых вторых этапов |
| S2-T, S2-M | Нормативное время и бонус за вторые этапы (без дедлайнов) |
| B-T, B-M | Нормативное время и бонус за брони |
| PP | Количество подготовок к выдаче |
| PP-T, PP-M | Нормативное время и бонус за подготовку к выдаче |
| CR | Количество приёмов документов |
| CR-T, CR-M | Время и бонус за приём документов |
| D | Бонус, вычитаемый за несоблюдение дедлайна |
| V | Отпуск в периоде (тогда производительность = 1) |
| ED-T | Время на обучение по нормативам |
| TW | Время, потерянное из-за технического простоя |

Индивидуальный рейтинг:

| Код | Смысл |
|---|---|
| P | Продуктивность |
| Exp | Процент соответствия должности (экспертность) |
| D(%) | Доля просроченных дедлайнов от числа вторых этапов |
| CR | Количество жалоб от клиентов и коллег |
| Fin | Размер «перекрытий» по вине сотрудника |
| T-N | Выработка рабочих часов |
| FBR | Запрошенная обратная связь по электронным визам |
| FB | Положительные отзывы с упоминанием сотрудника |
| RATE | Итоговый рейтинг за неделю |

Формула рейтинга: `50*(10-P) + Exp - D% - 10*CR - 0,5*Fin + 0,25*T-N + 10*FBR + 20*FB`

Вспомогательные вкладки: «График» (Р — рабочий день, Н — выходной, О — отпуск),
«Замечания» (дата, тип, описание, сотрудник, автор, вес, релевантность),
«Экспертность» (шкала 1–5 от «обучение назначено» до «автономия»),
«Запрос фидбека» (ID сделки, менеджер, дата), «Дедлайны», «Брони».

✅ Перенесено: первый и второй этапы по полям сделки «Менеджер ОО 1й ЭТАП» (574024) и
«Менеджер ОО 2й ЭТАП» (427128), выручка и возвраты по второму этапу, а также просрочка
дедлайна — «Дата бонуса ОО 2й ЭТАП» (446802) позже «Дедлайна ОО» (577948). Значения-
заглушки в этих полях («АКК», «БОТ», «Запись не требуется», «Оформление не требуется»)
отсеиваются сами: они не совпадают ни с одним сотрудником amoCRM.

❌ Не перенесено: нормативное время и бонусы по этапам, брони, подготовка к выдаче,
приёмы документов, экспертность, жалобы, перекрытия, запросы фидбека и отзывы. Часть
из них вводится руками и автоматической не станет; брони и подготовка к выдаче
достаются из amoCRM, но требуют разбора истории статусов.

## 4. Что спросить у руководителей

1. РОП: по какому фильтру берётся «Количество сделок по новым заявкам» — оплаченных
   сделок за неделю у менеджера меньше, чем стоит в файле.
2. Плинер: нужны ли в рейтинге нормативы времени и бонусы, или достаточно этапов,
   просрочки и возвратов.
3. Руководители ОРК: готовы ли перейти с модели загруженности в минутах на факт из
   amoCRM, и если да — какие типы задач соответствуют каким активностям.
